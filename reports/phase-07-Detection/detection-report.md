# Home SOC Lab — Phase 07 Detection Report

## 1. Objective

The objective of this phase is to identify and document suspicious or notable network activity using evidence collected during previous SOC lab exercises.

## 2. Detection Source

The investigation uses network reconnaissance and packet-capture evidence collected from the isolated Home SOC Lab.

Evidence reviewed:

- `nmap_scan.txt`
- `logs/kali-ping.pcap`

## 3. Detection

Network communication was observed between the Kali security-testing system and the Ubuntu monitoring system.

Kali:
- IP: 192.168.56.102

Ubuntu:
- IP: 192.168.56.101

ICMP echo requests and corresponding echo replies were observed in the packet capture.

## 4. Detection Logic

A basic network monitoring rule can flag repeated ICMP communication between monitored hosts for further investigation.

Example condition:

- Source: 192.168.56.102
- Destination: 192.168.56.101
- Protocol: ICMP
- Event: Echo request/reply

## 5. Analysis

The observed traffic was generated intentionally inside the authorized Home SOC Lab.

The traffic therefore represents expected lab activity rather than a confirmed malicious incident.

However, the same detection technique can be useful for identifying unexpected ICMP communication in a production environment.

## 6. Severity

**Informational**

Reason:

The traffic was generated by an authorized security-testing system inside the controlled laboratory network.

## 7. Recommended SOC Response

If similar traffic appeared unexpectedly in a production environment:

1. Identify the source and destination hosts.
2. Determine whether the communication is authorized.
3. Review packet captures and host logs.
4. Check for additional suspicious activity.
5. Escalate if the traffic cannot be explained.

## 8. Conclusion

Phase 07 demonstrates the basic SOC detection workflow:

**Observe → Detect → Investigate → Classify → Respond**

The detection was documented using evidence collected during previous Home SOC Lab activities.
